## 三类必须人工复核

### 1. 真机麦克风输入（AI 无法听）

- **批 5 让位语义**：AI 朗读中（任意句） → 用户说「嗯」 → AI 跳当前句 + 字幕立刻消失 + 1.5s 静默
- **批 4 emotion 标签**：让 LLM 输出 `你好<break 300ms>世界` → 听顺序为你好 + 300ms 静音 + 世界（非「你好世界」连读）
- **中文识别基线**：说中文日常句 → partial 字幕实时显示中文 + final 准确 ≥ 95%（cold start 后立刻可用）
- **唤醒词**（可选，issue #10 + 2026-09-18 真机修复后）：配置 wakeWord（建议 3-4 字，如「你好小李」）后 →
① **连说**：一口气说「你好小李，帮我查下天气」→ 草稿应为「帮我查下天气」（唤醒词被自动剥掉、**不截断**、不含唤醒词）；
② 同音字容错：把唤醒词首字/某字说错一个（如「你好小里」）→ 仍能唤醒；
③ 待机反馈：待机态说话 → 状态条显示「说『x』开始 · 实时转写」；
④ **唤醒后长停顿**：只说「你好小李」，停 2-3 秒再补命令 → 命令仍被识别（命令窗口，不回待机）；⑤ **朗读后立即喊**：等 AI 刚朗读完就立刻说「你好小李，<命令>」→ 能唤醒且命令完整（修复前此场景必挂：TTS 回声污染段首）；
⑥ 打断后：AI 朗读中开口打断 → 回待机态，重说唤醒词 + 命令 → 完整识别；
⑦ 段首毒化：先说一句无关话，停顿 ≥1.5s，再说唤醒词 + 命令 → 唤醒且只发命令；
⑧ 边界确认：切到 `hold` 或 `manual` 打断 → 唤醒词不再生效（预期，非 bug）；朗读期只说唤醒词不打断（预期）。
（默认 wakeWord 为空，未配置则跳过）

- **Issue #15 批 1 打断抢救（ADR-0012）**：AI 朗读中开口打断，说一句完整话（如「帮我查下天气」）→ 打断生效后草稿/发出的消息应含**从开口起**的完整内容（修复前只剩打断生效后的尾巴、长句整段丢失）。必测两档：① **外放**（原生 AEC 生效，detect 落 auto）② **耳机**；每档听 salvage 段转写纯度——句首不应混入 AI 朗读词的杂字（抢救锚点=语音起始前 ~250ms，AEC 残差外的尾音理论上被剥掉）；纯附和（只说了「嗯」）打断 → **不得**作为消息发出（backchannel 弃段守卫）。异常逃逸：外放无原生 AEC 的劣声学环境若抢救段出现乱码前缀 → 设置页关「打断语音抢救」回退丢句行为。
- **Issue #15 批 2 运行中插话**：让 AI 执行一个耗时任务（如「读一下这个仓库的所有文件」）→ 任务执行中途开口说一句话 → 消息应**尽快到达**（下一个 step 边界被消费，不等任务结束；等待发送区不停留十几秒）；若看到「等待发送」区停留 → 回退队列路径已兜底（行为不劣于修复前），但请记录当时是否 running。附带观察：消息上屏比输入框发送略慢半拍（steer 直发不走 composer 本地回声，durable 准入时上屏——预期，非 bug）。
- **Issue #15 批 8 桌面端 Electron 冒烟（用户侧，Windows 宿主先例）**：在桌面端（真 Electron，非 headless）用 0.2.1-alpha.5 与 0.2.1-rc.2 两个核心各跑一次完整语音链（说一段话→识别→发送→回复→朗读→字幕）+ 设置卡片可达性（Account menu → Settings → 语音模式）。背景：服务器侧 rc.2 runtime 冒烟已全量通过、alpha.5 的设置卡片探针稳定失败但经发布包 0.7.25 A/B 实证非插件回归（compat-contract §20）——桌面端复跑用于关闭这两个遗留。
- **Issue #15 批 5 发送延迟解耦**：① 把「静音判定时长」调到最低档 500ms → 说一句长话（中间有自然停顿，如「帮我查一下…嗯…明天的天气」）→ 应仍作为**一条**消息发出（不被停顿切成多条）；② 默认档手感：说完话到消息发出约 2.7 秒（端点 1.5s+附加 1.2s，比修复前早约 0.3s——预期变化，非 bug）；③ 停顿中改主意继续往下说 → 定时器被取消、消息不发（累积语义保持）。
- **Issue #15 批 4 LLM 纠错（llmCorrect 默认关）**：设置页开「LLM 纠错」→ 说一句带同音字的整话（如「帮我查一下明天的天起」）→ 等自动发送 → 收到的消息应已纠错（「天气」）且语义未变；观察纠错等待约 1 秒内（超过说明模型慢，可关）。失败降级：断网/凭据失效时说一句 → 消息应按**原文**正常发出（不得阻断）。另：定稿耗时显示——说一段长话后静默，SenseVoice 定稿超过 2 秒时状态条应显示「识别中… Ns」递增（证明没卡死）。

### 2. 语音输出听感（AI 无法听 TTS 质量）

- **TTS Edge 中文女声**（默认 `zh-CN-XiaoxiaoNeural`）：自然度 / 流畅性 / 情感是否合格
- **TTS 本地 Kokoro vs Edge**：设置页切本地 Kokoro → 同句试听 → 听感差异是否可接受（vs Edge 主观对比）
- **字幕与 TTS 帧同步性**：final 文本滚动与 TTS 朗读相位对齐（口型/句末同步，不超前不滞后 > 500ms）
- **让位 1.5s 静默期间字幕确实丢**：AI 跳句瞬间 + 后续 1.5s 内 partial 字幕视觉消失（不留残余字符）

### 3. 用户主观判断

- **字幕字号 4 档清晰度**：12 / 14 / 18 / 24px 切换 → 30cm 视距读字幕是否清晰（vs 上次版本无回退）
- **浅色 / 深色主题对比度**：浅色主题下字幕白底深字 / 深色主题下深底亮字 → WCAG 对比 ≥ 4.5:1
- **让位「体感明显」度**：说「嗯」到 AI 跳句的可感延迟 ≤ 300ms（用户主观无卡顿感）
- **错误归类提示用户友好度**：TTS 试听 / 引擎下载失败 / 网络断连 → 提示文案是否人能直接看懂（非技术堆栈）
